# חקר Spinomenal European Roulette

## מטרה
לנתח את המשחק הקיים של Spinomenal כדי להבין:
1. איך הלקוח (browser) מתקשר עם השרת.
2. איזה בקשות נשלחות.
3. איזה תשובות מתקבלות.
4. איזה מידע מגיע מהשרת ואיזה מטופל בלקוח.

## כלים שבהם השתמשתי
- **Chrome DevTools** → Network tab
- **Chrome DevTools** → Console
- **View Source** לדף המשחק
- קישור לדמו: https://www.spinomenal.com/european-roulette/ (Fun Mode)

## ממצאים מהניתוח

### 1. ממשק המשתמש
- **מצב:** Fun Mode (חינם, ללא הרשמה)
- **יתרה התחלתית:** 5,000 מטבעות
- **טווח הימורים:** Min 0.01, Max 100
- **צ'יפים זמינים:** 0.01, 0.02, 0.05, 0.1, 0.3, 0.5, 1, 2, 5, 10
- **כפתורים עיקריים:**
  - **Spin** - ביצוע הסיבוב
  - **Clear All** - ניקוי כל ההימורים
  - **Undo** - ביטול ההימור האחרון
  - **Double Bet** - הכפלת ההימור הנוכחי
  - **Autoplay** - סיבוב אוטומטי
- **אפשרויות נוספות:**
  - **בחירת טיקט ספציפי או Random Ticket**
  - **היסטוריה** - תוצאות קודמות
  - **סאונד** - הפעלה/כיבוי
  - **הסבר** - חוקי המשחק

### 2. לוח ההימורים
- **מבנה זהה לסטנדרט:** 0, מספרים 1-36, תריסרים, 1:1, 2:1
- **סוגי הימורים נתמכים:**
  - **Straight Up** - מספר בודד (35:1)
  - **Red/Black** - אדום/שחור (1:1)
  - **Odd/Even** - זוגי/אי-זוגי (1:1)
  - **Low/High** - 1-18 / 19-36 (1:1)
  - **Dozens** - תריסרים 1st/2nd/3rd 12 (2:1)
  - **Columns** - טורים 2:1
- **סדר המספרים בלוח:** סטנדרטי (3,2,1 למעלה; 36,35,34 למטה)

### 3. הגלגל
- **37 מקטעים** (0-36) בצבעים ירוק, אדום, שחור
- **גלגל ריאליסטי** עם מסגרת עץ, מסמרים מתכתיים, ומרכז מוזהב
- **מצביע עליון** - מראה על המספר הזוכה
- **אנימציית סיבוב** ארוכה עם האטה חלקה
- **תצוגת תוצאה** במרכז הגלגל עם המספר הזוכה וסכום הזכייה

### 4. תקשורת עם השרת

**ממצא מרכזי:** Spinomenal **לא** משתמשת ב-REST API טיפוסי שגלוי ב-Network tab.

מהניתוח ב-DevTools → Network tab:
- רוב הבקשות הן לקבצים סטטיים:
  - `WebClient.js` - הקובץ המרכזי של המשחק (650KB)
  - `jquery.js`, `jquery-ui.js` - ספריות JS
  - `number_*.png` - תמונות המספרים
  - `chips_*.png` - תמונות הצ'יפים
  - `btn_*.png` - תמונות הכפתורים
  - `sound_*.mp3` - קבצי סאונד
- **לא זוהו בקשות XHR/Fetch גלויות** לבקשות סיבוב.
- **מסקנה:** התקשורת עם השרת מתבצעת כנראה ב-**WebSocket** (מוצפן, לא גלוי ב-Network tab הסטנדרטי).

**השלכות על המימוש שלי:**
מכיוון שלא הצלחתי לחלץ את הפורמט המדויק של הבקשות, החלטתי ליצור פורמט מבוסס על העקרונות הבאים:
1. **השרת הוא מקור האמת** - RNG בצד השרת בלבד.
2. **הלקוח שולח הימורים בלבד** - לא תוצאות.
3. **השרת מחזיר תוצאה מלאה** - מספר זוכה, זכיות, יתרה חדשה.
4. **JSON** כשפת התקשורת.
5. **שמות פרמטרים ברורים** - `bets`, `balance`, `winningNumber`, `totalWin`.

## מסקנות

1. **הבנתי את זרימת המשחק:**
   - טעינה → בחירת הימור → סיבוב → תוצאה → עדכון יתרה.
2. **הבנתי מה השרת אחראי עליו:**
   - RNG (מחולל מספרים אקראיים) - בצד השרת.
   - חישוב זכיות.
   - אימות יתרה.
3. **הבנתי מה הלקוח אחראי עליו:**
   - ממשק משתמש.
   - ניהול מצב מקומי של הימורים.
   - אנימציית גלגל.
   - הצגת תוצאות.
4. **לא הצלחתי לחלץ את הפורמט המדויק** של הבקשות (בגלל WebSocket מוצפן), לכן יישמתי פורמט סטנדרטי דומה.
