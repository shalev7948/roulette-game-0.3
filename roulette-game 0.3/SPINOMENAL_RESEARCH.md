# חקר Spinomenal European Roulette

## כלים
- Chrome DevTools → Network tab
- Chrome DevTools → Console
- View Source

## ממצאים מהניתוח

### 1. ממשק המשתמש
- **מצב:** Fun Mode (חינם, ללא הרשמה)
- **יתרה התחלתית:** 5,000 מטבעות
- **טווח הימורים:** Min 0.01, Max 100
- **צ'יפים זמינים:** 0.5, 1, 2, 5, 10
- **כפתורים:** Clear All, Undo, Autoplay, Double Bet, Spin
- **אפשרויות:** Random Ticket, היסטוריה, סאונד

### 2. לוח ההימורים
- **מבנה זהה לסטנדרט:** 0, 1-36, תריסרים, 1:1, 2:1
- **סוגי הימורים:** Straight, Red/Black, Odd/Even, Low/High, Dozens, Columns
- **תשלומים:** 35:1, 1:1, 2:1 (סטנדרטיים)

### 3. הגלגל
- **37 מקטעים** (0-36)
- **גלגל ריאליסטי** עם עץ ומתכת
- **מצביע למעלה** (0)
- **אנימציית סיבוב** עם עצירה חלקה

### 4. תקשורת עם השרת
**ממצא מרכזי:** Spinomenal **לא** משתמשת ב-REST API טיפוסי.
מהניתוח ב-DevTools → Network:
- רוב הבקשות הן לקבצי סטטיים: JS, CSS, תמונות.
- הקובץ המרכזי הוא `WebClient.js` - כל הלוגיקה של המשחק.
- **לא זוהו בקשות XHR/Fetch גלויות לבקשות סיבוב.**
- **מסקנה:** התקשורת כנראה מתבצעת ב-**WebSocket** (מוצפן, לא גלוי ב-Network tab הסטנדרטי).

**השלכות על המימוש שלי:**
מכיוון שלא הצלחתי לחלץ את הפורמט המדויק של הבקשות, החלטתי ליצור פורמט דומה לסטנדרט של תעשיית ההימורים, שמכבד את העקרונות הבאים:
1. **השרת הוא מקור האמת** - RNG בצד השרת.
2. **הלקוח שולח הימורים** - לא תוצאות.
3. **השרת מחזיר תוצאה מלאה** - מספר זוכה, זכיות, יתרה חדשה.
4. **JSON** כשפת התקשורת.

## מסקנות

1. **הבנתי את זרימת המשחק** - בחירת הימור → סיבוב → תוצאה → עדכון יתרה.
2. **הבנתי מה השרת אחראי עליו** - RNG, חישוב זכיות, אימות יתרה.
3. **הבנתי מה הלקוח אחראי עליו** - ממשק, אנימציה, ניהול מצב מקומי.
4. **לא הצלחתי לחלץ את הפורמט המדויק** של הבקשות (בגלל WebSocket מוצפן), לכן יישמתי פורמט סטנדרטי דומה.
